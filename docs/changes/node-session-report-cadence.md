# 忙碌节点会话上报节流

run 首轮仍必须成功上报会话；随后使用单调时钟，在上次上报完成后至少 interval 秒、下一次领取前再次上报。队列连续有任务时不再每项都扫描会话目录；空闲轮询、独立心跳、结果确认后连续领取不变。到期上报拒绝仍在领取前退出并清理线程，不吞错误。

按开发技能采用主循环局部 deadline，不增加线程、缓存会话内容或外部依赖。

## 验证

新增 3 个可控时钟用例，覆盖忙碌队列间隔内跳过上报、边界到期上报/拒绝、慢上报从完成时计时与空闲后刷新。测试只替换节点模块 time 对象，不修改 threading 时钟，实际心跳线程均清理。

实测 `.venv/bin/python -m pytest -q`：267 passed in 2.33s；`.venv/bin/python -m compileall -q src`、`git diff --check` 通过。

## 证据边界

调度时间来自注入时钟，不是墙钟延迟实测；验证上报与领取调用顺序，未测真实目录扫描成本、CPU 或吞吐收益。网络与执行器为替身，无真实模型、微信或远程节点调用，无外部接口异常。

interval 是最小上报间隔，不是严格刷新周期：长任务期间仍等执行结束才刷新会话，独立心跳不受影响。尚无增量上报，仍存在每次完整扫描成本。结果持久化补报仍未完成。回退只移除 deadline 判断并恢复每轮上报，不改存储。
