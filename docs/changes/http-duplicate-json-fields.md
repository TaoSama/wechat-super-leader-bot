# 拒绝 HTTP JSON 重复字段

控制面使用 object_pairs_hook 在构建每一层 JSON 对象时检查重复键，不再静默保留最后一个值。同值重复、Unicode 转义后同名以及数组内嵌对象重复字段均返回 400，复用固定 invalid UTF-8 JSON 错误，不向响应暴露字段名或值。不同对象各自包含相同字段名仍合法。

按 go 技能的最小完整变更流程，仅修改请求解析和测试，不改变业务调度规则、系统配置或外部服务。

## 验证

新增 7 个回环 HTTP 用例：text 异值/同值重复、chat_id 重复、message_id 重复、转义同名、节点 sessions 嵌套重复、合法中文及幂等键透传。非法消息断言未调用业务处理；节点测试不提供 nodes 对象，确保请求在节点业务访问前已返回 400。

实测 `.venv/bin/python -m pytest -q`：355 passed in 2.75s。
`.venv/bin/python -m compileall -q src` 与 `git diff --check` 均通过。

## 证据边界

- HTTP 使用真实本机临时端口，业务处理使用替身；未验证微信平台、真实模型或跨机网络。
- 测试数量与耗时来自 pytest 输出，无性能推算；耗时仅为单次观测，不构成性能基准。
- 无外部接口调用或采集异常；响应断言与业务调用记录交叉检查拒绝行为。
- 本轮不解决结果 outbox、节点身份 fencing、任务归属权限和 app-server 生命周期问题。

测试关闭临时服务并等待服务线程退出，未新增常驻进程。回退本改动只需移除解析 hook 和相应测试；没有持久数据格式变更。
