# 启动模式冲突提前拒绝

argparse 解析后、业务初始化前校验运行模式。demo、serve、node-agent、check、微信模式之间互斥；微信 login 可组合 poll-once 或 daemon，但两种轮询不可同时指定。节点缺少或只含空白的名称/管理 token 在创建数据目录前返回参数错误（退出码 2）。无参数原行为不变。

按开发技能复用标准 argparse.error，不增加依赖、不修改系统环境或凭据。

## 验证与证据边界

新增 25 个用例：19 对冲突模式、4 种节点缺参、2 种合法登录轮询组合。冲突测试禁止业务对象/预检初始化；节点缺参实测数据目录未创建；合法组合用替身验证 login 后进入 poll，不扫码或联网。

验证命令：`.venv/bin/python -m pytest -q`、`.venv/bin/python -m compileall -q src`、`git diff --check`。实际 CLI 函数与文件系统断言交叉核对，不证明真实服务启动成功。无性能推算、外部接口异常。未校验所有非模式参数组合，例如非节点模式提供 node-name 仍可被忽略。结果持久化补报仍待完成。

回退只移除 parse_args 后的新校验并恢复节点分支缺参检查，不涉及任何存储迁移。
