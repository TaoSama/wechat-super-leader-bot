# 串行节点逐条领取任务

HTTP `/nodes/<name>/tasks` 明确传入 limit=1，不再沿用注册表 API 默认批量 10 条。串行节点只为本次将要执行的一项取得租约，避免第一项上报失败退出时，后续未执行项也成为 running 并最终 uncertain。NodeRegistry 内部批量 API 不变，HTTP 响应仍是 tasks 数组。

按开发技能最小改动原则仅修改 HTTP 调用参数，不改任务状态机或自动重排队。

## 验证

新增两个真实回环 HTTP 用例，队列中预置三项：首项成功/上报失败后均只有一项离开 queued，剩余两项随后仍能领取，执行器没有重复执行。注册、领取和成功上报使用真实本机服务，失败用替换上报函数注入。

实测 `.venv/bin/python -m pytest -q`：261 passed in 2.23s；`.venv/bin/python -m compileall -q src`、`git diff --check` 通过。测试服务器及线程已关闭。

## 证据边界与代价

未连接微信或真实模型、远程机器。上报失败是测试注入，不是外部事故；数据库状态与执行调用计数交叉验证。未做吞吐或延迟测量，不能宣称性能提升。

节点 run 仍在每轮完成后等待 interval，所以批量任务吞吐可能降低；本轮优先限制未执行任务被预占。并发 HTTP 请求仍可分别领取不同任务，并不强制整个节点只能有一个 running。领取响应丢失仍会使那一项进入不确定状态；结果持久化和领取幂等未实现。

回退仅恢复 HTTP 领取默认参数并移除本轮常量/测试，不改变已有任务数据。
