# 派发命令的空白解析

`/dispatch` 按精确命令词匹配，使用最多两次空白分割识别节点与任务。多空格、tab、换行或全角空格不再产生空节点；缺节点/任务时返回用法，不进入注册表抛错。任务正文内部空白、引号、代码不经 shell 解析，沿用入口 strip 的首尾处理。节点名仍不支持包含空白。

按开发技能采取最小路由修复，不修改节点派发事务、鉴权或稳定消息去重。

## 验证与证据边界

新增 11 个用例，覆盖五种分隔符、正文保全及重复消息、五种缺参、命令前缀和未授权请求。实测 `.venv/bin/python -m pytest -q`：298 passed in 2.47s；`.venv/bin/python -m compileall -q src`、`git diff --check` 通过。

测试使用临时 SQLite，路由返回与持久化 payload/条数相互核对；没有启动执行器、发送外部消息或读取真实凭据。未运行真实微信 daemon 重试循环，因此只证明这些输入不再从 handle 抛出解析导致的派发错误，没有网络故障或时延推算。其它命令的空白兼容未在本轮统一修改。回退只恢复 dispatch 分支两行及移除本轮测试。
