# 持续目标编排合同

本变更已随 `08e260a` 部署；Air 专用原会话两轮结果驱动闭环见 [真实验收](../2026-10-13-live-goal/VERIFICATION.md)，开发及首次资格失败见 [验证记录](VERIFICATION.md)。独立于已确认固定计划；目标调度器仍在同一 Controller 内，复用模型、CommandService、原 Daemon 和 PostgreSQL，不启动新 Agent 后端。

## 用户授权

自然语言 `propose_goal` 只生成预览。用户必须回复 `确认目标 <UUID>`；模型不能确认，重复确认不能生成新目标。预览完整展示目标、逐项完成条件、精确 node/session/route、每目标有序技能摘要、禁止事项、目标结果在所选会话间共享、动态决定任务的权限和预算。未显示的内容不能获得授权。

最多 4 个明确的既有原生会话，1–8 条完成条件，最多 12 次任务派发、24 轮模型决策、24 小时；这些是上限，不是自动给用户的默认授权。调用方须在预览明确实际值。每轮模型内部可能按已有客户端策略做最多 3 次 HTTP 尝试。目标文字/限制并非下游 Agent 的硬隔离，原会话自身权限仍然有效。

每聊天固定计划与持续目标最多一个未结束授权。blocked 保留此位置，只有取消或到期才释放。普通查询不清除待确认目标。取消目标仅撤销后续派发权，不终止原会话当前执行；已有 admitted 请求可能已经发送。

## 持久闭环

1. 原子确认目标并保存不可变授权。与固定计划确认共用聊天事务互斥。
2. 没有在途任务时，用同目标命令的精确 completed/turn/output 生成不可变证据（SHA256、长度、裁剪标志）。不读其他历史、聊天或计划作为授权资料。
3. CAS 领取独立的模型决策 lease，在领取时消耗一次决策预算。模型调用不在数据库事务中。
4. 纯决策工具只允许 next / complete / blocked；无发消息、改记忆、签发登录链接等写工具。下一步只能选冻结范围内的一个目标，最多明确选取 3 个先前结果作为资料；任务和输入全文先保存再领取发送。
5. CAS 提交模型结果时再次检查 lease、revision、授权期限、允许名单、输入证据。晚到结果不得覆盖取消或新 lease。纯决策 lease 到期可重新判断，发送 attempt 永久不可重领。
6. 下一步等待冻结路线的发送资格，不因忙/离线消耗发送 attempt。先永久保存 claim，再调用 CommandService，并在实际发送前复查同一授权。
7. pending/accepted 等待；uncertain、身份/证据不一致、失去确认的发送 claim 都停止，不新建 requestId 重试。已知失败也停下供用户核查，不自动重复有副作用的动作。
8. 所有动作完成并不等于目标完成。complete 必须覆盖每条条件，引用本目标真实完成且非空、未裁剪的结果。UI/通知必须注明这是基于记录的模型判断，而非独立业务证明。

## 生命周期与恢复

状态 active / blocked / completed / cancelled / expired。blocked 不反复调用模型；明确原因及需补充信息，用户可取消后重新授权。目标过期照常退出 blocked。查询和 Web 投影只读，不隐式恢复或派发。

模型请求失败保留脱敏分类并进入 blocked；模型 lease 中进程退出，恢复后在 lease 到期及剩余预算内允许重新判断。已经保存的动作、永久发送 claim、确定性 requestId 和命令记录保证不会因模型重判或重启重发。取消接口必须可在后台模型等待时及时处理。

## 验收门槛

- 一次确认后，没有新用户消息也能根据第一轮结果产生不同的第二轮任务并完成条件判断。
- 双调度器、迟到模型、重启、发送 claim 后崩溃、重复消息不重复派发。
- 目标范围/技能/预算/期限不可扩张，跨聊天读写拒绝，目标与固定计划互斥。
- 取消穿过模型调用及发送 guard 时仍禁止后续；accepted 不算完成；uncertain 不重发。
- 裁剪/缺失/矛盾结果不能支持完成；输出中要求换目标、泄漏或解除限制的文字不成为授权。
- PostgreSQL 真实事务、HTTP/WS 与 Web 只读实时投影均需验证，不能只靠 MemoryStore。
- 真实微信、真实模型和原会话部署验收仍独立记录，不以合成测试冒充。
