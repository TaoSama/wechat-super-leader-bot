# 微信传输层长文本截断提示

## 改动

共享 Markdown 渲染函数在格式转换完成后计算长度。超过应用默认 4000 字符预算时，为 `\n\n[内容过长，已截断]` 预留空间；返回值（含提示）不超过预算。短文本和恰好达到上限的文本不增加提示。自定义上限小到无法容纳提示时使用单个省略号；零上限返回空串，负上限仍报错。

按 go 技能的最小完整变更原则，复用两个 Markdown 公共入口和现有 mock/iLink send 路径，不新增发送请求或自动分页。

## 验证

新增 `tests/test_wechat_truncation.py` 的 16 个用例，覆盖两个格式入口、中文/emoji、零/小/默认边界、转换后恰好达到预算以及两种 transport 的最终发送内容。

实测 `.venv/bin/python -m pytest -q`：210 passed in 2.14s。`.venv/bin/python -m compileall -q src`、`git diff --check` 均通过。

## 证据边界与剩余工作

- iLink 请求被测试替身截获，未读取真实凭据、未向微信发消息，未进行微信客户端显示验证。
- 4000 是已有应用字符预算，不是本轮确认的微信协议限制；Python 字符长度不等于 UTF-8 字节数或用户可见字素数，组合 emoji 仍可能在截断处分开。
- 提示仅说明传输层截断，不提供全文恢复或分页。路由层 `/codex`、`/fork` 的尾部 3500 字符切片及 `/tasks` 摘要仍是独立待办。
- 没有模拟真实网络时序，没有性能/延迟推算。本轮无外部接口调用、异常或重试；单元边界测试与最终发送 payload 测试一致。
- 回退只需恢复渲染函数末尾切片及两个默认参数、移除本轮常量和测试，不影响已存数据。
