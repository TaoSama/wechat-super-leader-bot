保留 `list_sessions()` 默认最近 100 条，增加可选 `limit`（None 为不限）。`get(session_id)` 使用全部记录查找，不再因会话跌出最近 100 条而误报不存在。

匹配文件使用流式迭代与 deque 保留最后 20 个物理行，避免 read_text 把整份日志加载到内存。空行跳过；损坏 JSON 记录返回 `parse_errors`，包含绝对行号、列号和解析器诊断，不回显日志原文；完整记录仍在 `events` 返回。文件读取错误仍向上抛出，不将读失败误报为无记录。

本轮按开发技能做项目文件读取修复；OpenAI Docs 的适用边界不要求为通用文件逻辑查询产品协议，未更改或声称验证 Codex 协议。

## 证据边界

全部使用合成日志，没有读取用户真实会话或调用真实模型。内容断言及禁止 read_text 的测试验证实现路径，但未做峰值内存/延迟测量；deque 只限制保留的行数，不限制单行长度，仍需顺序读完整文件。查找仍扫描并排序目录、读取元信息，未实现索引。不是官方 rollout schema 兼容性验证，未修复现有 session_meta 类型/UUID 校验或文件并发消失问题。

损坏记录诊断仅覆盖最后 20 个物理行；不会扫描报告更早的坏记录。未测试真实并发日志追加；请求看到的是读取时的快照近似而非事务快照。本轮无外部接口异常，无推算性能数字。

没有新增微信查看会话历史命令，此变更仅完善已有管理器 API。回退仅恢复管理器列表/读取逻辑并移除本轮测试；不改动日志数据。
