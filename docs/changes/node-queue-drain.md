# 逐条领取时只在空队列等待

节点 run 在 dispatch_once 返回非空且已确认的结果列表后，立即进入下一轮会话上报和单项领取；只有空列表才等待 interval。执行失败但 failed 终态已确认，也可继续领取；结果未确认抛出的异常仍退出并清理心跳，不继续领取或重跑。

此变更补齐此前 HTTP 单项领取引入的任务间固定等待，保持每次只预占一项。按开发技能复用既有返回值与异常契约，不新增线程或批量预取。

## 验证

新增 3 个测试：真实回环 HTTP 主循环连续处理三项成功/失败任务，数据库均有对应终态后才首次调用空闲等待；另测试未确认结果立即退出不再次领取。执行器与等待函数使用替身，实际注册、会话上报、领取、状态写入和心跳线程清理均经过现有实现。测试服务器和线程均正常关闭。

实测 `.venv/bin/python -m pytest -q`：264 passed in 2.45s；`.venv/bin/python -m compileall -q src`、`git diff --check` 通过。

## 证据边界

未连接真实模型、微信或远程机器。测试验证 sleep 调用顺序及参数，不是实际等待时长或吞吐测量；没有推算性能数字。数据库终态与执行次数交叉核对，无外部接口事故。

忙碌队列下每项任务仍触发会话上报与扫描，短任务可能增加控制面压力；未实现独立上报节流。空闲仍按 interval 轮询。结果持久化、领取响应丢失恢复未完成。

回退仅恢复 dispatch_once 后无条件等待的两行，保留 HTTP 单项领取和既有错误处理。
