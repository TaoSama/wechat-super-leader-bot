# 节点心跳过期判断

## 变更

NodeRegistry 默认以 120 秒为心跳有效期，可通过构造参数 heartbeat_ttl 调整。
注册和合法心跳保存控制面 UTC 时间；列表动态计算在线状态，派发和领取均检查有效期。
达到有效期边界即离线，错误 token 不刷新时间，合法心跳可恢复。
兼容旧数据库的 SQLite UTC 时间字符串；损坏或未来时间戳按离线处理。
任务默认有 300 秒租约；及时心跳续租。过期执行转为 uncertain（结果待确认），不自动重新排队。节点重新注册也将旧 running 任务标记为 uncertain，避免新进程为旧执行盲目续租。原所属节点仍可回传迟到结果。

## 验证

`.venv/bin/python -m pytest -q`
本轮全量实测 49 passed。新增安全用例覆盖过期不可复活、节点重新注册、及时续租；原自动重派用例已改为禁止自动重派。

## 证据边界与后续

存活测试使用注入时钟，无等待采样；测试值不是实际网络延迟或生产可用性指标。
旧时间戳只有秒精度，新时间戳保留微秒；控制面系统时钟跳变可导致暂时误判。
未采集远程机器数据或微信消息；本轮没有外部接口调用失败或重试。
NodeAgent.run 现在以独立后台线程发送心跳，长任务期间仍能维持在线；心跳临时异常会在下个周期重试，不会中断当前任务。
过期检测由任务查询、心跳/续租、领取触发，没有独立扫描进程。uncertain 不等于执行失败；需核对外部副作用后再决定是否手动派发新任务。执行代次隔离、持久化结果重传仍未实现，不能宣称跨机恰好执行一次。当前离线只表示心跳超时，不证明机器宕机。
