# 结果确认响应被截断时重传

`response.read()` 在响应体短于 Content-Length 时抛出的 `http.client.IncompleteRead` 不属于既有 OSError/URLError 分支。将该异常纳入结果上报的有界重试，只重传同一个结果，不重新执行任务。原有最多 3 次、等待 1/2 秒、永久 HTTP 拒绝不重试的规则不变。未扩大为重试全部 HTTP 协议异常或无效 JSON。

## 验证

新增一个异常注入参数用例及两个真实回环 HTTP 用例。测试服务器声明完整响应长度，但只写部分响应并关闭连接：首次截断后恢复时确认成功；持续截断时尝试 3 次并传播 IncompleteRead；两种情况下执行器均只调用一次，所有上报内容相同。服务器与线程均在 finally 关闭。

实测 `.venv/bin/python -m pytest -q`：237 passed in 2.20s；`.venv/bin/python -m compileall -q src`、`git diff --check` 通过。

## 证据边界

异常类型由真实本机 HTTP 读路径触发，并与直接异常注入测试交叉验证。执行器为替身；未连接微信、模型、远程控制面或真实代理。等待通过替换 sleep 核对参数，没有测量真实重试耗时；无性能推算。本轮故障是主动构造的测试情景，不是外部接口事故。

仍没有结果持久化与重启补报，其他阶段的网络错误也未统一处理。本轮按开发技能限定为单个异常分类修复，未改系统配置或产生外部消息。回退仅移除 IncompleteRead 导入与捕获项及本轮测试。
