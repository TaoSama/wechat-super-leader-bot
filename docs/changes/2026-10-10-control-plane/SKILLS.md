# 节点技能目录与版本绑定

## 使用方式与执行边界

技能归属节点，不归属 Controller 文件系统。Daemon 在明确配置的目录里读取 SKILL.md，向 Controller 发布名称、简介、规范路径、路径标识和正文 SHA256；不上传完整正文，不执行技能中的脚本。Controller 只在认证后的 API 或模型工具结果中提供目录，不把技能元数据提升成系统指令。

模型可查询 `list_skills` 后，在待确认任务中选择一个技能引用（id + digest）。微信预览显示技能和版本，用户确认后才发送。Daemon 重新扫描并验证引用，然后将“读取该文件、核对版本、在当前任务范围内使用技能”的说明连同原任务发送给用户可见的已有会话。实际 Agent 仍需遵守原会话权限、完整读取技能及必要依赖。这不是 Controller 直接执行宿主机脚本，也不是创建隔离 worker。

## 配置

原生 Daemon 默认不扫描任何目录。使用标准 CLI 的重复 `--skill-root /absolute/path`，或环境变量 `SKILL_ROOTS`（绝对路径的 JSON 数组）指定目录；`--probe-skills` 只打印目录信息，不连接 Controller/Codex，不要求 token。

本机项目启动器 `node local.mjs --daemon` 默认将当前用户的 `.claude/skills` 与 `.agents/skills` 及其顶层安装软链别名显式配置为扫描根（包括这些别名的实际目标）；显式设置 `SKILL_ROOTS` 可以覆盖，设置 `[]` 禁用。更深层软链不能扩大范围，不会更改已有技能或系统配置。

目录和 SKILL.md 的软链须落在配置根内；根目录本身允许软链。遇到 SKILL.md 即停止向包内 references/assets 遍历；没有 SKILL.md 的 bundle 容器则继续找其安装包。目录深度、遍历规模、文件大小和目录记录数均有上限，避免遍历整个文件系统。路径 ID 来自规范路径 SHA256，同名技能不会被名称自动合并。受限目录或解析错误有诊断，不能把部分目录当成“全部技能”。

## 授权、持久化与失败语义

- `GET /v1/skills` 需要 Controller 管理凭证；模型调用前还有微信操作者允许名单。
- 技能只可附于 send，每个任务最多一个技能。不存在独立的 shell/run-script 工具。
- 技能引用保存在命令和计划中，幂等比较包含技能引用；同请求 ID 换技能须拒绝。
- 提计划、确认和 Daemon 派发前核对目录/版本；过期或丢失引用不能退化为普通 prompt 继续发送。
- accepted 仅表示技能任务输入已受理。技能是否被正确读取和执行仍要用原会话输出或终态验证。
- SHA256 绑定当前 SKILL.md，不是整个依赖目录的不可变快照。扫描与原会话读取之间仍有文件变更窗口，因此会话提示要求再次核对版本；这不能宣传成文件系统事务或完整供应链隔离。

## 验证范围

Go 测试使用临时技能目录和模拟会话适配器，验证扫描边界、技能变更后拒绝派发、原任务保留和重复命令回执。Controller 测试验证目录鉴权、计划确认、版本检查与幂等。真实 PostgreSQL 联调验证技能引用经计划/命令持久化、重启恢复和 wire 传递。真实宿主机扫描不等于真实技能执行完成，后者需用户指定测试会话。
