# 节点执行结果的文本契约

执行器返回非 str 时，节点将当前任务作为 failed 上报，结果为固定提示 `executor must return text`，不回显非法对象、不重新执行任务。服务端确认后继续处理批次后续任务。空字符串仍为合法成功结果。

异常 stderr 为 bytes 时以 UTF-8 替换模式解码；不支持的类型或空白 stderr 回退异常文本，异常文本为空则保留异常类型名，避免失败状态没有任何说明。既有字符串 stderr 保持优先。

按开发技能最小改动流程复用既有失败上报与确认逻辑，不改变服务端状态机、重试次数或执行次数。

## 验证

新增 10 个用例覆盖 None、数字、字典、列表、bytes 返回值，批次继续执行与每项仅执行一次，异常 stderr 解码/类型/空白以及合法空字符串。验证上报可 JSON 序列化。

实测 `.venv/bin/python -m pytest -q`：256 passed in 2.33s；`.venv/bin/python -m compileall -q src`、`git diff --check` 通过。

## 证据边界

执行器与上报接口为测试替身，未调用真实模型、节点或微信。结果及执行次数断言与 JSON 序列化检查一致；未验证真实远程状态落库，没有性能推算或外部接口异常。非法字节替换可能损失原始诊断字节，未保存原始二进制。

此处 failed 表示执行器未给出符合契约的结果，不证明任务没有产生副作用；不要自动重跑。结果可靠持久化仍未实现。回退仅移除本轮返回值校验和异常文本归一化及其测试，保留既有错误上报逻辑。
