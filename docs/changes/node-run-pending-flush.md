# 节点重新运行时优先补报终态结果

NodeAgent 在已有内存 pending 结果的情况下重新进入 `run()`，会先执行一次受身份绑定保护的结果补报，再进行会话目录上报和任务领取。这样，临时网络故障恢复后，失败的 session 上报不会继续阻挡已经完成的任务结果。

## 边界

这只覆盖同一个 NodeAgent 实例的恢复顺序。初始心跳成功和心跳线程启动仍在补报之前；初始心跳失败时不会补报。结果仍未落盘；进程退出、机器重启或实例被释放后，pending 结果无法恢复。`updated` 必须严格为 `True` 才会清除 pending；身份变化仍会拒绝补报。

## 验证

使用虚构控制面和 executor 的本机测试覆盖：pending 结果先补报成功后才调用 `report_sessions`；补报被拒绝时不会继续会话上报；全量测试通过。没有启动常驻节点、读取真实凭据或发送外部消息。
