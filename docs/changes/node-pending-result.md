# 节点结果在同一实例内补报

NodeAgent 在执行完成或失败后、发送终态前保存内存中的结果及领取时的 server_url/name/token。上报异常或确认被拒绝时保留结果；下一次 dispatch_once 只补报，不领取和执行新任务。只有 updated 严格为 True 才清除结果。register 在尚有结果待确认时拒绝操作；身份变更也拒绝补报，避免误用新身份报告旧任务。

## 范围与恢复方式

调用方须保留同一个 NodeAgent 实例，并在修复上报故障后再次调用 dispatch_once，或以原身份重新调用 run。当前 run 的恢复顺序为：初始心跳通过、启动心跳线程、补报 pending 结果、会话上报、领取新任务；会话上报不再是补报的前置条件，详见 [恢复顺序变更](node-run-pending-flush.md)。没有增加无限自动重试，原有三次短暂重试规则不变。

这不是磁盘 outbox：CLI 因异常退出、进程崩溃或实例被释放后，内存结果仍会丢失。身份检查也不是服务端 attempt/generation fencing。直接并发调用 dispatch_once 不受支持；生产控制面一次领取一条，兼容旧多条响应不保证恢复未执行的剩余批次。

## 验证与证据边界

本地 HTTP/SQLite 集成覆盖上报前故障与服务端保存后确认响应丢失：恢复时只补报，队列中另外两条任务保持 queued；补报后继续处理，三条任务各执行一次且全部 completed。executor 为替身，不调用真实模型。额外 10 个回归用例覆盖成功/失败结果恢复、拒绝确认后保留结果、服务地址/节点名/token 变化及重新注册拒绝。

最初实现时实测 `.venv/bin/python -m pytest -q`：366 passed in 2.67s；`.venv/bin/python -m compileall -q src`、`git diff --check` 通过。这是历史验证记录，不代表当前测试总数。初次全量测试发现旧集成用例假定可跳过未确认结果，已更新为先补报再领取，并增强最终三条 completed 的断言。

曾委派测试子代理，因尚未收到完成结果，中断后由主代理接手整理测试并统一验收。没有收到明确接口报错，不将该等待判定为接口故障。

未连接真实微信、跨机节点或读取真实凭据。不存在性能推算；测试时间仅为单次观测。没有本轮外部接口错误，不把模拟 TimeoutError 视为线上证据。持久化恢复、可信身份恢复及任务权限仍待完成。

回退仅移除内存 pending 状态与补报分支并恢复对应测试，不修改数据库结构。测试关闭回环服务，无新增常驻进程或备份。
