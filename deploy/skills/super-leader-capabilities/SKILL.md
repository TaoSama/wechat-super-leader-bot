# Super Leader Bot 功能说明

功能清单和场景在 [功能说明与场景](references/capabilities.md)。按用户问的范围选内容：

- 问全部功能：展示完整表格，每项功能配一个场景。
- 问单项功能：展示对应的表格行和场景。
- 比较 Plan 和 Goal：展示两行表格和两个完整场景。
- 问功能有什么用：说明机器人接手了哪些操作，用户得到什么结果。
- 问某功能现在能不能用：先用本轮的查询工具确认，再介绍确认过的功能。
- 问以前提过的需求：查原始用户记录，说明查到的要求。

用户其实是在下达任务时，照常执行，不介绍功能。
“会话”指电脑上的 Agent 对话，“微信聊天”指用户和机器人的对话。

## 表格格式

列名固定为：`分组`、`功能`、`你交代什么`、`机器人负责什么`。

- 第一列：写分组名称，每行保留所属分组。
- 第二列：写简短的功能名称。
- 第三列：写用户提供的对象、任务或时间。
- 第四列：用动词开头，写机器人的动作和结果。
- 每行介绍一项功能。单元格使用短语。

分组顺序固定为：基础功能 → 任务执行 → 多会话协作 → 定时与后台。
各组的功能顺序沿用功能说明表。图片回传、聊天记忆和 CLI 终端操作归入基础功能。

## 场景格式

先展示表格，再按相同的分组和功能顺序介绍场景。
每组场景前用独立加粗标签标出分组名称。
每项使用以下格式：

**用［功能名称］，你在微信说：**

> ［可以直接发送的指令］

［机器人如何处理］。［用户得到的结果或省下的操作］。

多步骤使用 `**步骤一 → 步骤二 → 结果**`。
根据结果选择步骤的场景，先写“它可能这样推进”。

全部功能的介绍保留每项场景。简版介绍保留总表和代表场景。
回复使用 Markdown 表格、独立加粗标签、引用和清晰分段。
长回复使用现有分段与发送流程。
结尾用一句话说明这组功能能替用户完成什么。

## 回复前检查

确认功能覆盖完整、名称一致、动作具体。
确认表格和场景的分组、顺序逐项对应。
确认每项都有微信指令和处理过程。
确认描述符合已核对的功能。
