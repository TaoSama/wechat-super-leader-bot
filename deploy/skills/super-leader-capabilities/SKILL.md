# Super Leader Bot 功能说明

帮助用户了解功能，并写出可以直接发到微信的指令。

## 选择内容

读取 [功能说明与场景](references/capabilities.md)。根据用户问题选择内容。

- 询问全部功能：展示完整表格，为每项功能提供一个场景。
- 询问单项功能：展示对应表格行和场景。
- 比较 Plan 和 Goal：展示两行表格和两个完整场景。
- 询问功能价值：说明机器人接手的操作，以及用户得到的结果。
- 询问当前可用功能：通过本轮查询工具核对，再介绍已确认的功能。
- 询问历史需求：查阅原用户记录，说明查到的要求。

功能介绍以文字示例展示用法。用户提出执行要求时，按现有任务流程处理。
功能事实以当前代码、工具和查询记录为依据。

## 写作方式

使用简短、具体的中文。每句话表达一个主要意思。

- 用主动句，写清楚谁做什么。
- 用明确的动词，例如“查询”“发送”“等待”“汇总”。
- 同一个概念使用同一个名称。
- 直接写功能、操作和结果。
- 把长句拆成按顺序排列的短句。
- 用具体场景说明功能价值。
- 保留示例中的任务对象、输入和完成条件。
- 将 Plan 写作“Plan：固定计划”，将 Goal 写作“Goal：持续目标”。
- 用“会话”指电脑上的 Agent 对话，用“微信聊天”指用户与机器人的对话。

## 表格格式

列名固定为：`分组`、`功能`、`你交代什么`、`机器人负责什么`。

- 第一列：写分组名称，每行保留所属分组。
- 第二列：写简短的功能名称。
- 第三列：写用户提供的对象、任务或时间。
- 第四列：用动词开头，写机器人的动作和结果。
- 每行介绍一项功能。单元格使用短语。

分组顺序固定为：基础功能 → 任务执行 → 多会话协作 → 定时与后台。
各组的功能顺序沿用功能说明表。图片回传、聊天记忆和 CLI 终端操作归入基础功能。

## 场景格式

先展示表格，再按相同的分组和功能顺序介绍场景。
每组场景前用独立加粗标签标出分组名称。
每项使用以下格式：

**用［功能名称］，你在微信说：**

> ［可以直接发送的指令］

［机器人如何处理］。［用户得到的结果或省下的操作］。

多步骤使用 `**步骤一 → 步骤二 → 结果**`。
根据结果选择步骤的场景，先写“它可能这样推进”。

全部功能的介绍保留每项场景。简版介绍保留总表和代表场景。
回复使用 Markdown 表格、独立加粗标签、引用和清晰分段。
长回复使用现有分段与发送流程。
结尾用一句话说明这组功能能替用户完成什么。

## 回复前检查

确认功能覆盖完整、名称一致、动作具体。
确认表格和场景的分组、顺序逐项对应。
确认每项都有微信指令和处理过程。
确认描述符合已核对的功能。
